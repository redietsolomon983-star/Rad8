What I Learned from Committing Every Day

I built this portfolio one day at a time, with a commit after each step. Here is what that habit taught me.

1. Small steps are easier to finish

"Build a portfolio" is a big and vague task. "Add the About section" is small and clear. Splitting the work into daily pieces meant I always knew what to do next, and I never felt stuck for long.

2. A history you can read

Looking at the commit list on GitHub shows the whole story of the project. Clear messages make it even better: 

git commit -m "Day 2: Add About and Skills sections"
git commit -m "Day 7: Add pure CSS dark mode"

When something breaks, I can see exactly which day introduced the change.

3. Mistakes become cheap

If a change goes wrong, going back to yesterday's version is easy because yesterday was saved. That makes it safe to experiment with new ideas, like animations or a dark mode.

4. It shows consistency

Employers who open a GitHub profile can see steady activity. Regular, honest progress says more than one huge upload.

Tips that helped me

  • Commit when something works, not only when you are done for the day.
  • Write the message as if explaining it to a teammate.
  • Run git status before committing to see what is included.
  • Push regularly so your work is also safe online.
